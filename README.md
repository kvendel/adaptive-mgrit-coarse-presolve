# Adaptive MGRIT Coarse Presolve

This repository contains the source code, execution scripts, numerical data, and plotting files accompanying the manuscript **"A Coarse Presolve Strategy for Adaptive Time Grid Construction in Multigrid Reduction in Time"**.

The repository is organized so that the numerical data used in the manuscript figures can be inspected and the figures can be regenerated without repeating the full HPC experiments. The C programs and Komondor SLURM scripts used to produce the data are also included.

## Repository contents

- `xbraid/`: XBraid dependency, included as a Git submodule and pinned to a specific commit.
- `experiments/fig7/` through `experiments/fig14-16/`: files associated with Figures 7-(14-16) of the manuscript.
  - `src/`: C source files.
  - `scripts/`: SLURM batch and execution scripts used on Komondor.
  - `results/`: numerical output files used by the plotting code.
  - `Makefile`: compilation rules for the C programs in the directory.
- `experiments/plotting/`: the Jupyter notebook and Python module used to generate the manuscript figures.
- `Makefile`: top-level build interface for XBraid and all experiment programs.

## Scope of the reproducibility material

This repository contains the source codes, execution scripts, numerical results, and plotting routines for the new computational experiments reported in Figures 6-16 of the manuscript.

Figures 2-4 revisit numerical results and refinement strategies presented in the authors' earlier work.

## Obtaining the repository

Clone the repository together with the XBraid submodule:

```bash
git clone --recurse-submodules https://github.com/kvendel/adaptive-mgrit-coarse-presolve.git
cd adaptive-mgrit-coarse-presolve
```

If the repository was cloned without submodules, initialize XBraid with:

```bash
git submodule update --init --recursive
```

The recorded XBraid commit can be displayed with:

```bash
git -C xbraid rev-parse HEAD
```

## Software requirements

The full experiments require:

- a C compiler;
- an MPI implementation;
- GNU Make;
- XBraid, supplied through the `xbraid/` submodule;
- a SLURM environment for the supplied Komondor batch scripts.

Regenerating the figures from the included result files requires Python, Jupyter, and the Python packages imported by the notebook and its accompanying module.

## Building on Komondor

The reported experiments were compiled on the Komondor HPC system using the default Cray programming environment. The Cray compiler wrapper `cc` was used for both C and MPI C compilation.

From the repository root, build XBraid and all experiment programs with:

```bash
make
```

The top-level Makefile passes the following compiler settings to XBraid and to the experiment Makefiles:

```text
CC=cc
MPICC=cc
MPICXX=CC
```

The upstream `xbraid/makefile.inc` file is not modified.

Useful build targets are:

```bash
make xbraid              # build XBraid only
make fig7                # build programs associated with Figure 7
make fig16               # build programs associated with Figure 16
make list                # list detected parallel and sequential sources
make clean-experiments   # remove experiment executables
make clean-xbraid        # remove XBraid build products
make clean               # remove all build products
```

Executables are created next to their corresponding C source files in the `src/` directories.

On another system, compiler variables may be overridden. For example:

```bash
make CC=gcc MPICC=mpicc MPICXX=mpicxx
```

The SLURM scripts are Komondor-specific and may require changes to account, partition, module, resource, and execution settings on another HPC system.

## Running the experiments

The SLURM scripts used for the manuscript experiments are stored in the `scripts/` directory belonging to each figure. Submit the required script with `sbatch`, for example:

```bash
sbatch experiments/fig7/scripts/<script-name>
```

Parallel executables are launched with `srun` by the supplied batch scripts. The scripts write the numerical output needed for the corresponding figure to its `results/` directory.

The included `results/` files are the data used for the submitted manuscript. Runtime measurements are system dependent, so newly measured wall-clock times may differ because of hardware, MPI configuration, process placement, network behavior, and system load.

## Regenerating the figures

The manuscript figures are generated by the notebook and Python module in:

```text
experiments/plotting/
```

Start Jupyter from that directory:

```bash
cd experiments/plotting
jupyter notebook figures.ipynb
```

Open the included notebook and run its cells in order. The plotting code reads the committed data from the `results/` directories under `experiments/fig7/` through `experiments/fig16/`.

Because the numerical result files used in the manuscript are included, access to Komondor is not required to regenerate the figures.
